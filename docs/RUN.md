# SKYFALL — запуск, деплой и диагностика

Короткая инструкция: как запустить игру локально, как поиграть вдвоём и как
опубликовать её в интернете. Всё, что нужно, — Node.js и браузер.

## 1. Требования

| Что | Зачем |
| --- | --- |
| **Node.js 18+** (`node -v`) | локальный сервер и сборка |
| **Chrome / Edge / Firefox** | WebGL2 и WebRTC |
| **Аккаунт Cloudflare** (бесплатный) | только для игры по интернету |

Видеокарта нужна любая: на слабой игра сама снижает разрешение и отключает
часть эффектов.

## 2. Локальный запуск

```bat
start.bat
```

или вручную:

```bash
node server.js
```

Браузер откроется на <http://localhost:8080>. Если не открылся — зайдите сами.

Другой порт:

```bat
set PORT=9000 && node server.js
```

Только статика, без серверной части, тоже подойдёт — игре нужен любой
HTTP-сервер, потому что ES-модули не работают через `file://`:

```bash
python -m http.server 8080
```

> Без `server.js` останется одиночная игра: сигнального API для кооператива
> не будет, и клиент честно об этом скажет.

## 3. Кооператив в локальной сети

1. Хозяин запускает `start.bat` и смотрит адрес в консоли — строка
   **«В сети»**, например `http://192.168.1.10:8080`.
2. Друг открывает этот адрес в браузере.
3. Хозяин: **КООПЕРАТИВ → СОЗДАТЬ КОМНАТУ**, получает код из 4 символов.
4. Друг: **КООПЕРАТИВ**, вводит код, **ПОДКЛЮЧИТЬСЯ**.
5. Хозяин: **НАЧАТЬ ОПЕРАЦИЮ**.

Соединение прямое (WebRTC), сервер только знакомит игроков. В одной сети
пакеты идут напрямую по локальным адресам.

Если друг не открывает страницу — Windows спросил про брандмауэр, разрешите
Node.js в частных сетях (или добавьте правило для порта 8080).

## 4. Публикация на Cloudflare Workers

Игра полностью serverless: Worker раздаёт файлы и держит сигнальный API
на Durable Object. Игровой трафик через Cloudflare не идёт.

```bash
npm install        # один раз: ставит wrangler
npx wrangler login # один раз: открывает браузер
npm run cf:deploy  # сборка public/ + деплой
```

Wrangler в конце печатает адрес вида
`https://skyfall.<ваш-поддомен>.workers.dev` — это и есть ссылка для друзей.
Если это первый Worker в аккаунте, Cloudflare может попросить зарегистрировать
поддомен `workers.dev` — сделайте это один раз в панели **Workers & Pages**.

Что происходит под капотом:

1. `npm run build` (`tools/build-public.mjs`) собирает `public/`:
   `index.html`, `styles.css`, `src/`, `vendor/`.
2. `wrangler deploy` заливает Worker из `worker/` и эти файлы как Static Assets.
3. Комнаты обслуживает Durable Object `Room` (SQLite-backed, доступен на Free).

Проверка перед деплоем, локально:

```bash
npm run cf:dev
```

Поднимется `http://localhost:8787` с настоящим Worker и эмуляцией Durable
Objects. Кооператив там тоже работает — можно открыть два окна.

Полезное:

```bash
npx wrangler tail              # живые логи Worker
npx wrangler deployments list  # история версий
```

Переименовать Worker: поле `name` в `wrangler.jsonc` (адрес изменится).
Свой домен: **Workers & Pages → skyfall → Settings → Domains & Routes**.

### GitHub Actions

Один раз добавьте ключ Cloudflare — дальше каждый пуш в `master`/`main`
деплоит игру сам.

1. **Cloudflare → My Profile → API Tokens → Create Token**.
2. Шаблон **«Edit Cloudflare Workers»** → **Create Token** → скопируйте
   значение (показывается один раз).
3. **GitHub → Settings → Secrets and variables → Actions → New repository
   secret**:
   - имя: `CLOUDFLARE_API_TOKEN`
   - значение: токен из Cloudflare.
4. Следующий пуш запускает `.github/workflows/cloudflare.yml`.

Что делает workflow:

- проверяет, что секрет задан (иначе пропускает деплой и остаётся зелёным);
- ставит wrangler;
- сам определяет аккаунт по токену через `tools/cf-account.mjs`;
- собирает `public/` и вызывает `wrangler deploy`;
- пишет адрес игры в Summary запуска.

Если аккаунтов несколько, добавьте второй секрет `CLOUDFLARE_ACCOUNT_ID`
с нужным id — он используется вместо автоопределения.

Запустить вручную: **Actions → Deploy SKYFALL to Cloudflare → Run workflow**.

Проверить токен локально:

```bash
CLOUDFLARE_API_TOKEN=... node tools/cf-account.mjs
```

### Лимиты бесплатного плана

Сигналинг — это единицы запросов на комнату плюс редкий heartbeat.
Лимит Free — 100 000 запросов в день, то есть тысячи комнат; бой Worker
не нагружает вообще. Ограничение Free: Durable Objects только с SQLite —
у нас именно такой (`new_sqlite_classes` в `wrangler.jsonc`).

## 5. TURN, если прямое соединение не проходит

Обычно хватает STUN. TURN нужен, когда оба игрока за строгим (симметричным)
NAT или в мобильной сети: тогда прямой канал не собирается.

На **https://skyfall.akimus.ru** и **https://xrip.github.io/skyfall/** TURN
подключается автоматически. При создании
или входе в комнату Worker выдаёт временные реквизиты на 24 часа. Браузер
выбирает прямой путь, когда он доступен, иначе использует релей на
`62.84.172.208:3478` по UDP или TCP. Для сетей, которые блокируют эти порты,
доступен TURN через TLS: `turn.skyfall.akimus.ru:443`. Игрокам ничего вводить
не нужно.

Для локального сервера или своего TURN можно задать настройки вручную.
Они имеют приоритет над автоматическими реквизитами.

В окне **КООПЕРАТИВ** раскройте **«Свой TURN-сервер»** и заполните:

| Поле | Пример |
| --- | --- |
| адрес | `turn:turn.example.com:3478` |
| логин | `skyfall` |
| пароль | `••••••` |

Несколько адресов можно перечислить через запятую. Настройки хранятся
в `localStorage` браузера и применяются к следующему соединению.

Свой TURN поднимается, например, на [coturn](https://github.com/coturn/coturn)
(нужен VPS с открытыми портами 3478 и диапазоном relay-портов). Бесплатные
публичные TURN-серверы не дают гарантий — лучше свой.

Настройка рабочего сервера и проверки: [TURN.md](TURN.md).

## 6. GitHub Pages

Workflow `.github/workflows/pages.yml` публикует статическую версию.

1. **Settings → Pages → Source → GitHub Actions**.
2. Пуш в `master` или `main` — сайт появится на
   `https://<логин>.github.io/skyfall/`.

На `https://xrip.github.io/skyfall/` работает и кооператив. Статические файлы
отдаёт GitHub Pages, а запросы комнат идут на `https://skyfall.akimus.ru/api/rooms`.
Worker автоматически выдаёт временные TURN-реквизиты. Поля своего TURN
оставьте пустыми; если раньше сохраняли их, нажмите кнопку сброса настроек.
Игроки на GitHub Pages и основном сайте могут входить в одну комнату.

## 7. Если что-то не работает

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «Сигнальный сервер недоступен» | недоступен Worker или открыт статический сервер без API | проверить доступ к `skyfall.akimus.ru` либо запустить `node server.js` локально |
| «Комната не найдена» | опечатка в коде, истекли 20 минут или другой адрес сайта | создать комнату заново, проверить адрес |
| «В комнате уже двое» | к коду уже подключён игрок | дождаться или создать новую комнату |
| «Прямое соединение не установилось» | строгий NAT | указать TURN (раздел 5) |
| Друг не открывает адрес в локальной сети | брандмауэр Windows | разрешить Node.js в частных сетях |
| `EADDRINUSE` при запуске | порт 8080 занят | `set PORT=9000 && node server.js` |
| Чёрный экран, ошибка в консоли | нет WebGL2 или старый браузер | обновить браузер, включить аппаратное ускорение |
| После обновления игры старая версия | кэш браузера | `Ctrl+F5` |

Диагностика WebRTC: откройте `chrome://webrtc-internals` во время подключения
и посмотрите, дошло ли до `connected` и какие кандидаты собрались.

## 8. Что куда деплоится

```
index.html, styles.css, src/, vendor/   →  Static Assets (и Pages, и Worker)
worker/                                 →  Cloudflare Worker
worker/room.js                          →  Durable Object комнаты (только SDP)
server.js                               →  локально, не деплоится
public/                                 →  генерируется `npm run build`, в git не хранится
```

Локально и в Worker используется **один и тот же** протокол `/api/rooms*`,
поэтому поведение кооператива в разработке и в проде совпадает.
